Evidence

This page separates what exists now from what remains unproven. If a claim is not on the supported side, we are not making it.

Last reviewed on publication of this build

What the evidence supports

Systems and specifications carry between engines; code often does not.

Rules, state definitions, data structures, equations, edge cases, expected behaviour, test cases and architecture decisions survive an engine change. Engine-specific gameplay code is assessed separately and largely rewritten.

Desk42 is a single-player Windows PC game built in Unity.

The player operates inside an institutional claims system where evidence, policy, procedure, adjudication, queues, appeals and precedent create persistent consequences. It currently exists as a bounded playable causal slice.

Brawler is in development in Unreal Engine.

Its system-level proposition is a deterministic reactive field whose state is authoritative for movement, hazards, actor exposure and combat consequences, rather than a cosmetic effect layer.

The reaction-diffusion methods are established; the implementation is ours.

We claim a gameplay implementation and a toolchain built on established reaction-diffusion methods, not ownership of the underlying mathematics.

Founder capability is inspectable in public.

SatyBT is a founder-created behaviour-tree framework published under the MIT licence. It stands as evidence that we can design, test, document, package and maintain reusable technical infrastructure.

The commercial model is deliberately narrow.

Premium downloadable PC games through digital distribution, beginning with Desk42 and followed by Brawler. Reusable technology is an internal margin and execution advantage, not a product.

What we do not claim

Not one proprietary engine.

We do not sell, license or claim a named proprietary game engine. There is no separate customer, package, price, sales channel or licence revenue in the base case.

Not direct code reuse across engines.

We do not claim that every line of code transfers between Unity and Unreal, and we do not claim that changing engine is cheap.

Not a finished product.

The current Desk42 implementation is a bounded causal slice. It is not described as near-complete, production-ready or market-validated.

No performance figures until measured.

No runtime benchmark, frame budget or simulation-scale figure is published here. Those follow a frozen build and recorded measurements, not an estimate.

No market validation yet.

External playtests, store-page behaviour, wishlist data and purchase-intent work have not been completed. Comparable titles establish plausible categories and price bands; they do not evidence our demand.

No price, date or scale commitments.

No release date, sales figure, final price, team size, partner, award or press claim appears on this site, because none is currently supported by inspected evidence.

SatyBT

SatyBT is a behaviour-tree framework written by the founder and published under the MIT licence. It is included here because it is inspectable: the design, the tests, the documentation and the packaging can be read by anyone assessing whether this studio can build and maintain reusable technical infrastructure.

It is not a Dark Lattice product, it is not sold, and it is not part of the revenue model.

Possible future direction

A third game combining persistent institutional systems with the reactive field has been discussed internally. It is not committed. No work is scheduled, no budget is allocated, and nothing in the plan depends on it. It would only be considered if the first two products showed it was worth building.

Scalability position

Dark Lattice does not depend on copying one engine-specific codebase across every product. Its scalability comes from accumulating reusable technical knowledge, system architecture, proprietary implementations, production infrastructure, IP and market evidence across multiple releases. Where engine-specific code must be rewritten, the underlying problem has already been designed, tested and understood, reducing repeated discovery and development risk.
